== Prerequisites

* xref:00-setup.adoc[Cluster setup] is complete
* `oc whoami --context cluster` prints your student id
* You are in the repository root

== How it works

A container is a running process from an image.
A Pod is the smallest object OpenShift runs. It holds one or more containers.
Containers in one Pod share the network and can share a volume.
OpenShift schedules the Pod onto a node. You do not choose the node.

== Steps to apply

[#compare]
=== 1. Compare Kubernetes and OpenShift

*What:* Read the objects that both platforms share, and the objects OpenShift adds.

*Why:* Later labs use Kubernetes objects and one OpenShift object, the Route.

[cols="2,2,3",options="header"]
|===
| Topic | Kubernetes | OpenShift

| Run a process
| Pod
| Pod

| Keep it running
| Deployment
| Deployment

| Address inside the cluster
| Service
| Service

| Address outside the cluster
| Ingress, after you install a controller
| Ingress is included. Route is the native API

| Isolation
| Namespace
| Project. A Project is a Namespace with OpenShift metadata

| CLI
| kubectl
| oc. oc accepts kubectl commands

| Default security
| You choose the policy
| Restricted by default
|===

[#single-pod]
=== 3. Run one container

*What:* Create a Pod that runs only the httpd container.

*Why:* You see the smallest object OpenShift can run before you add a second container.

icon:clock[] ~1 minute (image pull)

[.console-input]
[source,bash]
----
oc apply -f 01-pods/pod.yaml -n "${WORKSHOP_NAMESPACE}" --context cluster
oc wait --for=condition=Ready pod/workshop-web -n "${WORKSHOP_NAMESPACE}" --context cluster --timeout=180s
----

.Verify: The Pod is Ready

====

----

[.console-output]
[source,bash]
----

workshop-web   1/1     Running   0          30s

====

'''

[#sidecar]
=== 4. Add a sidecar

*What:* Replace the Pod with two containers that share an emptyDir volume.

*Why:* A sidecar can write a file that the web container serves. The Pod is still one object.

A Pod spec does not update in place. Delete the Pod first.

icon:clock[] ~1 minute (image pull for the sidecar)

[.console-input]
[source,bash]
----
oc delete pod workshop-web -n "${WORKSHOP_NAMESPACE}" --context cluster --wait=true
oc apply -f 01-pods/multi-container-pod.yaml -n "${WORKSHOP_NAMESPACE}" --context cluster
oc wait --for=condition=Ready pod/workshop-web -n "${WORKSHOP_NAMESPACE}" --context cluster --timeout=180s
----

The sidecar writes `Hello from the sidecar` into the shared volume.
httpd serves that file.

.Verify: Both containers are Ready and the file is shared
[%collapsible]
====
[.console-input]
[source,bash]
----
oc get pod workshop-web -n "${WORKSHOP_NAMESPACE}" --context cluster
oc exec workshop-web -c httpd -n "${WORKSHOP_NAMESPACE}" --context cluster -- cat /var/www/html/index.html
----

[.console-output]
[source,bash]
----
NAME           READY   STATUS    RESTARTS   AGE
workshop-web   2/2     Running   0          40s
Hello from the sidecar
----
====

== What this solves (compared to a local process)

[cols="2,3",options="header"]
