= Lab 4 - ConfigMaps and Secrets: change the app without a new image
:page-time: 45
include::_attributes.adoc[]

Time: 45 minutes.

You move the HTML page into a ConfigMap.
You put a lab token in a Secret.
The page shows the ConfigMap text. The page does not show the token.

== Prerequisites

* xref:03-ingress.adoc[Lab 3] is complete
* The Route `workshop-web` exists
* You are in the repository root

== How it works

A ConfigMap holds plain text that a Pod can mount as files.
A Secret holds a value you do not want in a ConfigMap or in the image.
This lab token is a sample string, `lab-sample-token`. It is not a production password.
OpenShift still stores the Secret separately from the ConfigMap.

== Steps to apply

[#configmap]
=== 1. Create the ConfigMap and the Secret

*What:* Create both objects before you change the Deployment.

*Why:* The Deployment mounts them. The Pod stays pending if either object is missing.

[.console-input]
[source,bash]
----
oc apply -f 04-config/configmap.yaml -n "${WORKSHOP_NAMESPACE}" --context cluster
oc apply -f 04-config/secret.yaml -n "${WORKSHOP_NAMESPACE}" --context cluster
----

.Verify: Both objects exist
[%collapsible]
====
[.console-input]
[source,bash]
----
oc get configmap/workshop-web-page secret/workshop-web-token -n "${WORKSHOP_NAMESPACE}" --context cluster
----

[.console-output]
[source,bash]
----
NAME                         DATA   AGE
configmap/workshop-web-page  1      5s
secret/workshop-web-token    1      5s
----
====

'''

[#secret]
=== 2. Mount the files and read them

*What:* Roll out the Deployment that mounts the page and the token. Then read both.

*Why:* The page comes from the ConfigMap. The token stays in the Secret file.

icon:clock[] ~30 seconds (rollout)

[.console-input]
[source,bash]
----
oc apply -f 04-config/deployment.yaml -n "${WORKSHOP_NAMESPACE}" --context cluster
oc rollout status deployment/workshop-web -n "${WORKSHOP_NAMESPACE}" --context cluster
oc exec deploy/workshop-web -c httpd -n "${WORKSHOP_NAMESPACE}" --context cluster -- cat /etc/workshop/token
HOST="$(oc get route workshop-web -n "${WORKSHOP_NAMESPACE}" --context cluster -o jsonpath='{.spec.host}')"
curl -sk "https://${HOST}"
----

NOTE: `curl -sk` skips TLS verification. A production client should trust the cluster CA instead.

.Verify: The token is in the file and the page shows only the ConfigMap heading
[%collapsible]
====
[.console-output]
[source,bash]
----
lab-sample-token
<html><body><h1>Hello from the ConfigMap</h1></body></html>
----
====

WARNING: Do not put a real password in this Secret manifest. The file is in Git so the lab can mount a known sample.

== Reset

Delete the Secret and the ConfigMap after you restore the Lab 2 Deployment.
The Lab 2 Deployment does not mount those objects.
If you delete the ConfigMap first, the running Pod can keep a deleted volume until you roll the Deployment.

[.console-input]
[source,bash]
----
oc apply -f 02-deploy/deployment.yaml -n "${WORKSHOP_NAMESPACE}" --context cluster
oc rollout status deployment/workshop-web -n "${WORKSHOP_NAMESPACE}" --context cluster
oc delete secret workshop-web-token -n "${WORKSHOP_NAMESPACE}" --context cluster --ignore-not-found=true
oc delete configmap workshop-web-page -n "${WORKSHOP_NAMESPACE}" --context cluster --ignore-not-found=true
----
